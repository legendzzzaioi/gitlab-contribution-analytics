# GitLab Contribution Analytics

面向自建 GitLab CE/EE 的代码贡献分析系统。系统通过 GitLab REST API 定时采集数据，将 GitLab 组、项目、用户、提交及代码增删行统计持久化到本地 MySQL。前端报表仅查询本地数据，不直接请求 GitLab API，实现数据采集与报表查询解耦。

## 一、功能特性

### 1. 数据源管理
- 配置 GitLab 服务地址、Personal Access Token 或 Project Access Token。
- 配置根项目组 ID，指定需要同步的项目范围。
- 支持 GitLab API 连接测试。
- 支持同步周期配置。
- Token 加密存储，前端仅返回掩码。

### 2. 数据采集
- 支持首次全量同步和后续增量同步。
- 定时执行 GitLab 数据采集任务。
- 支持手动触发全量或增量同步。
- 记录同步运行历史、执行状态及错误信息。
- 同步 GitLab 组、子组、项目、用户和提交记录。
- 采集每次提交的代码新增行数和删除行数。

### 3. 贡献分析
- 按日期、项目组、项目和贡献者筛选。
- 展示提交数量、代码新增行数、删除行数及净增行数。
- 提供贡献趋势、贡献者排行榜和项目贡献排行。
- 支持贡献者详情和提交明细查询。
- 支持 CSV 导出。
- 支持贡献者邮箱别名映射，避免同一人员因使用不同 Commit Email 被拆分统计。

### 4. 用户认证
- 内置 JWT 登录认证。
- 提供管理员账号用于首次部署和本地体验。
- 支持后续接入公司 SSO 或 LDAP。

## 二、系统架构

```text
                   GitLab CE / EE
                         │
                         │ GitLab REST API
                         ▼
                 Gin 定时采集任务
                         │
                         ▼
                       MySQL
                         │
                         ▼
                  Gin 聚合查询 API
                         │
                         ▼
                Vue 3 + ECharts
                   中文管理看板
```

系统采用采集与查询分离的架构：

- **数据采集层**：Gin 后端定时调用 GitLab REST API，完成全量或增量数据同步。
- **数据存储层**：MySQL 保存 GitLab 组、项目、用户、提交及贡献统计数据。
- **业务接口层**：Gin 提供聚合查询、筛选、分页、导出和管理接口。
- **前端展示层**：Vue 3 + ECharts 提供独立的中文管理看板。

前端浏览看板时不会实时扫描 GitLab，所有报表均基于本地 MySQL 数据查询，降低 GitLab API 请求压力，提高查询效率。

## 三、快速开始

### 1. 环境要求

- Docker
- Docker Compose
- 可访问 GitLab API 的网络环境

### 2. 配置环境变量

修改 `docker-compose.yml` 中的配置，至少替换以下参数：

- `JWT_SECRET`：JWT 签名密钥。
- `ADMIN_PASSWORD`：管理员初始密码。

生产部署时应使用足够强度的随机密钥和密码。

### 3. 启动服务

在项目根目录执行：

```bash
docker compose up --build -d
```

查看服务运行状态：

```bash
docker compose ps
```

查看服务日志：

```bash
docker compose logs -f
```

### 4. 登录系统

浏览器访问：

```text
http://localhost:8088
```

使用管理员账号登录。

默认开发账号：

```text
用户名：admin
密码：change-me-now
```

该账号仅供首次本地体验，正式部署前必须修改。

### 5. 配置 GitLab 数据源

登录后进入“数据源配置”页面：

1. 填写 GitLab 服务根地址，例如 `https://gitlab.example.com`。
2. 填写 Personal Access Token 或 Project Access Token。
3. 填写根项目组数字 ID。
4. 点击“测试连接”，确认 GitLab API 可正常访问。
5. 保存数据源配置。
6. 执行首次全量同步。

根项目组 ID 可以留空。留空时，系统将尝试同步当前 Token 可见的全部顶级项目组及其下属资源。

## 四、数据采集与同步策略

### 1. 首次全量同步

首次运行时，系统根据配置的数据源和根项目组范围，采集：

- GitLab 组及子组。
- GitLab 项目。
- GitLab 用户及提交作者信息。
- 项目提交记录。
- Commit 新增行数和删除行数。

### 2. 后续增量同步

默认每 12 小时执行一次增量同步。

增量任务以最近一次成功同步时间为基础，并向前回看 15 天，以降低 API 分页、时间边界及数据延迟造成的遗漏风险。

所有提交采用幂等写入，重复采集不会重复累计统计数据。

### 3. 提交采集接口

通过 GitLab REST API 获取项目提交：

```text
GET /projects/:id/repository/commits?with_stats=true
```

利用 `with_stats=true` 获取提交统计信息：

- `additions`：新增代码行数。
- `deletions`：删除代码行数。
- `total`：代码变更总行数。

### 4. 提交去重规则

提交使用以下组合键进行幂等识别：

```text
project_id + sha
```

同一个项目中的同一 SHA 只保存一次，重复同步执行更新，不重复累计。

### 5. 默认统计口径

- 默认以项目默认分支为数据源。
- Merge Commit 不计入普通代码行统计，避免合并提交造成统计膨胀。
- 提交新增、删除行数以 GitLab 返回的 Commit Stats 为准。
- 贡献者归属优先使用管理员维护的邮箱别名映射。
- 未映射的提交邮箱可自动创建贡献者记录。
- 贡献者统计用于研发活动分析，不应单独作为个人绩效评价依据。

## 五、系统页面

### 1. 总览

支持按时间范围、项目组、项目和贡献者筛选，展示：

- 提交总数。
- 代码新增行数。
- 代码删除行数。
- 代码净增行数。
- 贡献趋势。
- 贡献者排行榜。
- 项目贡献排行。

### 2. 贡献者

展示个人贡献情况：

- 提交数量。
- 代码新增和删除行数。
- 参与项目。
- 最近提交记录。
- 个人贡献趋势。

支持查看贡献者详情及维护邮箱别名。

### 3. 提交明细

展示具体 Commit 信息：

- 提交时间。
- 所属项目。
- 提交 SHA。
- 提交作者。
- 提交说明。
- 新增行数。
- 删除行数。

支持分页查询、条件筛选、GitLab 页面跳转和 CSV 导出。

### 4. 同步中心

提供数据同步管理功能：

- 手动触发全量同步。
- 手动触发增量同步。
- 查看同步运行状态。
- 查看历史同步记录。
- 查看同步失败原因和错误信息。

### 5. 数据源配置

提供 GitLab 数据源管理功能：

- GitLab 服务地址配置。
- Token 配置及掩码展示。
- 根项目组配置。
- API 连接测试。
- 同步周期配置。
- GitLab 组和项目同步管理。
- 贡献者邮箱别名映射。

## 七、生产部署与安全建议

### 1. GitLab Token 权限

建议创建专用服务账号，使用仅具备目标项目组访问权限的 Token。

优先授予：

```text
read_api
```

不要直接使用个人管理员 Token。

确保服务账号对需要统计的项目具有足够的读取权限。

### 2. Token 安全

当前示例将 GitLab Token 保存在数据库中，前端仅返回掩码。

生产环境建议进一步改为 KMS/Vault 等密钥管理服务引用，避免明文密钥长期保存在业务数据库中。

### 3. 登录认证

内置 JWT 账号主要用于初始部署和受控内网环境。

生产环境建议：

- 接入公司 SSO 或 LDAP。
- 或在 Nginx 等反向代理层增加身份认证。
- 限制管理入口的访问来源。
- 定期轮换管理员密码和 JWT 密钥。

### 4. 数据库维护

建议：

- 定期备份 MySQL。
- 为提交表保留必要的查询索引。
- 重点关注以下索引：

```sql
commits(project_id, authored_at)
commits(user_id, authored_at)
```

- 根据实际数据量定期检查查询性能和数据库容量。
- 生产环境不要直接暴露 MySQL 服务端口到公网。

### 5. 统计结果说明

Commit 新增、删除行数只能反映代码变更规模，不能完整代表研发工作量。

在使用贡献排行时，建议结合提交质量、Merge Request、代码评审、缺陷修复和项目实际交付情况综合分析，避免单纯以代码行数作为绩效指标。
